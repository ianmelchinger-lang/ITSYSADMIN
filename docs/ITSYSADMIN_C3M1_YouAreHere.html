The drive that looks done

A ticket lands on your desk: give the new warehouse team a shared drive.

You open the server and find two things that look like progress. An install wizard has finished with a green message — File and Storage Services, installation succeeded. And a folder someone created has already been shared on the network, so it turns up for machines that go looking.

The warehouse has been waiting two days. Everything on the screen says you are one click from closing this.

Is the ticket done?

What the screen didn't tell you

What the server actually provides

The wizard's green message is a record of what you asked for. Ask the server itself which roles it is running — a role is a named capability the machine has been given, like serving files — and the answer comes back:

File and Storage Services: not installed.

The success you saw was about your request. It was never about the machine.

Who can open the drive

The folder is shared, so it is reachable. But making something reachable and deciding who may reach it are two different settings. The share's access list — the record of who is allowed in — still names a broad default group, not the warehouse team.

"Shared" answered a different question than "shared with the right people."

So here is the capability this asks for, before any tool matters:

Ask the server what it provides instead of trusting what a tool reported. And treat a folder's existence and its access list as two separate things you set on purpose. That is the move that has to be in place before you hand anyone a drive you can account for — and it is what turns this back into the afternoon's work it looked like.
