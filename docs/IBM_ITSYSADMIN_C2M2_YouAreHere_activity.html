Install and Update Software with Package Management

Two hosts. One installed-package list. Are they on the same path?

You've just joined the operations team. Someone hands you a status check that ran on two storefront hosts overnight. Both reports list the same package, at the same version.

Host A — installed packages

httpd2.4.57-2
openssl-libs3.0.7-2
sem-checkout-svc4.1.0-1

Host B — installed packages

httpd2.4.57-2
openssl-libs3.0.7-2
sem-checkout-svc4.1.0-1

Nothing else has been shared with you yet — no configuration, no history, no ticket. Just these two lists.

Based on what you're looking at, are Host A and Host B on the same path going forward?

Answer locked. You can't change it now — that's the point.

What the installed list left out

Host A — enabled repositories

sem-baseenabled
sem-security-updatesenabled

Host B — enabled repositories

sem-baseenabled
sem-security-updatesdisabled

The installed-package list can't hold this information, no matter how carefully you read it — because it isn't a fact about what's installed. It's a fact about which sources the host is allowed to ask. A repository is configured separately, in its own file, and it can be switched on or off without changing a single line of what's already there. Host A can still see tomorrow's security update. Host B can't, and its installed list will never say so.

The capability this module builds: reading which repositories are enabled as a separate question from what's installed — deliberately, every time, because the installed list will never ask it for you.
