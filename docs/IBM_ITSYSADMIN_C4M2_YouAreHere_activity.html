The folder that wasn't closed

During an access review, a warehouse role account opens a shared folder that holds the finance team's budget file. The finance operations lead is certain that folder is closed to anyone outside finance. It isn't.

You're the administrator asked to close it. You haven't looked at the folder's settings yet — only the report.

Access to a shared folder like this one is controlled in two places at once: a network share permission, and a file-system permission underneath it. Before you open either one, decide what you'd do.

Your call

If you had to make one change right now to close this folder to the warehouse role, what would you change?

You won't be able to change this once you lock it in.

Today, over the network, the warehouse role account can actually reach Modify — it can open, edit, and save the budget file. That's the file-system entry doing the granting; the share, set to Full Control for Authenticated Users, isn't restricting anything here.

What closed this cleanly was never about which setting felt like the obvious place to look. It was knowing exactly which entry, on which layer, was granting the access in the first place — and touching only that one.
