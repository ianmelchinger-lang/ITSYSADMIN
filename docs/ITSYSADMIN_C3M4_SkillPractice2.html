Predict Which Scripts the Server Will Run

A refusal tells you where a file came from, not what is wrong with it.

Every Windows machine carries an execution policy: a setting that decides which saved scripts the shell will run. The policy judges a file by where it came from and whether it carries a valid digital signature. A signature identifies who published the file and shows that nobody has changed it since.

Below are six things an administrator might try to run on the retailer's back-office server. Sort each one by what the server will do.

The back-office server

This server's policy

Scripts written on this server run. Scripts from anywhere else run only if they carry a valid signature.

Anything that arrived by download or as an email attachment counts as from anywhere else.

    The same six, on a different server

    Now each of these is tried on a second server. The files are identical. Only the machine's rule is different.

    The second server's policy

    Scripts run only if they carry a valid signature, wherever they were written.

    Nothing in any file has been edited.

      The policy belongs to the machine, not to the script. When a script is refused, read the message and name the control behind it. Then find out where the file came from and which policy is in force. Those two facts tell you whether you need a signed copy, a different machine, or a word with whoever owns the policy.
