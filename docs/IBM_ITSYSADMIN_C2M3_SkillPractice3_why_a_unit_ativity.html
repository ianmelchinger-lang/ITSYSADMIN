Trace the Failure Upstream

A unit reporting failed names the unit. It doesn't diagnose the cause. systemd starts units in an order computed from declared dependencies, not a fixed script — so the unit everyone notices is often the last domino, not the first.

For each case, one unit is the one people noticed failing. Read every unit's status, then pick the one actually worth checking first — the thing the rest of the chain was waiting for.

Pick the unit to check first in each case.

One of these cases isn't what it looks like tonight. Same chain, different unit actually broke — see if you're reading statuses or just reading position.

The named unit is where the failure surfaces, not necessarily where it started. Reading every status in the chain, before touching anything, is what finds the actual blocker.
