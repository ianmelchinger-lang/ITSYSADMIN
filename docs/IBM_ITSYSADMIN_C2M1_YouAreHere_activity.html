The Command That Said Nothing

A storefront host is behind on patching with a seasonal peak closing in. Before anything else, you've been asked to clear space — move one shared working file out of a crowded directory and into an archive branch elsewhere on the host.

What you typed

$mv Q3_vendor_terms.xlsx /srv/archive/finance/

No output. No error. Just the prompt again, waiting for the next command.

The file moved from a shared working directory that the whole storefront team can reach — /srv/storefront/shared/finance-wip — into an archive branch you picked because it had room — /srv/archive/finance.

Before you check anything — can Finance still open this file?

What the command never checked The file's own record is identical in both columns — same name, same size, same modified time. What changed sits one level up: the archive branch is restricted to IT, and that restriction reached down onto everything placed inside it, including a file that had nothing to do with the restriction and never asked for one.

A command that returns without complaint is telling you the operation finished. It was never in a position to tell you whether finishing was correct — that depends on something outside the command entirely: what the destination allows.

That's the piece this module builds: for any file on a host, knowing what it inherits from the branch you put it in, before someone has to tell you it's missing.
