Compare Results, Isolate the Fault

Fault isolation means narrowing a failure to one link by comparing tests. A test that passes clears every link it crossed. A test that fails tells you one of its links is broken, without saying which. Put two results side by side and you can strike some links and keep others.

The same request in every case

The management machine cld-lnx-02 opens the storefront by its name, storefront.corp.example. That request fails. Assume exactly one link is broken, and that every test reports honestly on the links it crosses.

The tests, by how far each one reaches

  • Test 1 reaches this machine's own address, 10.240.1.4.
  • Test 2 reaches the gateway out of sn-mgmt.
  • Test 3 reaches cld-lnx-01 at 10.240.0.4.
  • Test 4 reaches the web service at 10.240.0.4, TCP 443.
  • Test 5 is the users' own request, by name.

Mark where the break could still be

Each pair shows two results and the links each test crossed. For each pair, tick every link where the one break could still be. One tick means you have located it. Several ticks mean you have narrowed it, and that is a correct answer when the results allow no more.

Move one verdict in each pair

Keep the tests the same. In each pair, one result now comes out the other way. Mark again where the break could be.
