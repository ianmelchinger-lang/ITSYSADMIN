Test the Description Before You Hand It Over

A saved script is only shareable if its description answers what a colleague would otherwise ask you.

The back office has saved its folder cleanup as a script. A colleague will run it next week while you're away. At the top of the file sits a short description block: plain sentences that tell a reader what the script does, what it acts on, and how to run it.

What the script does

  1. List every file in the report-export folder.
  2. Keep only the files older than 30 days.
  3. Delete each file it receives.

Sort the draft description

For each line, choose the question it answers for your colleague. Then decide whether the description is ready.

Description block, top of the cleanup file

    Could your colleague run this safely without asking you anything?

    Months later, the cleanup changes

    The description now has a line that names which files the script deletes. Then someone edits step 2 of the script. Nobody touches the description.

    Description block, unchanged since the edit

      The scope line is the one most likely to drift, because it describes the filter, and the filter is the part people edit. Change the filter, and change that line in the same sitting.

      You can try this on any script you've saved: add three lines at the top saying what it's for, what it acts on, and how to run it. Then hand it to a colleague and ask them to run it without asking you anything. Each question they do ask points to a line the description still needs.
