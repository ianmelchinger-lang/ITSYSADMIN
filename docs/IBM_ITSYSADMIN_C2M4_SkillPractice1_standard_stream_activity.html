Two streams, one redirect

A command's results and its errors travel on separate channels. Redirecting one never touches the other.

A nightly backup script writes two kinds of lines as it runs: a line for every directory it copies successfully (its results, standard output — stream 1), and a line when it can't read something (its errors, standard error — stream 2).

Last night, someone ran it like this: only standard output was redirected, into backup.log. Standard error was left alone — it still goes wherever it always goes, by default: the screen.

Each line below is labelled with the stream the script actually sent it on. For each one, say where it ends up.

Now she changes her mind

This time, only standard error is redirected, into error.log. Standard output is left alone. Nothing here is graded — just watch where each line lands as you flip the redirect.
