Which route missed this, and why?

Every way of discovering what exists in an environment has a blind spot built into how it works. Read what happened in each case, then pick the route whose specific limit explains the miss.

The four routes
  • A system reporting on itself — only visible while it's switched on and reachable.
  • A platform's own listing — only shows what runs on that specific platform.
  • A purchase record — only shows what was bought through the channel it tracks.
  • A handover note from a previous colleague — only reflects what they knew on the day they wrote it.
Warehouse print and label host
Checked at 9 a.m. using a tool that asks each machine to report its own status. This host is powered down overnight on a fixed schedule and hadn't come back online yet — it didn't appear anywhere in the results.
Head office file server
Someone opened the cloud platform's account and read off every resource it listed. This server runs entirely on-premises, so it never appeared in that list at all — not because it was hidden, but because the list only covers that one platform.
Checkout service
This service shows up fine in the cloud platform's listing, since it runs there. But procurement has no record of it anywhere — a contractor built it under a fixed-fee contract that never itemized individual services, so no purchase order was ever raised for it specifically.
Old staging host
A handover note written eighteen months ago describes this host accurately for that date. It doesn't mention that the host was quietly repurposed for a different project last quarter, and there's no way to go back and ask the note anything further.

One more, on its own

Same four routes. A new component this time.

Regional kiosk terminal
A self-service kiosk at a store location connects to the network only during business hours. Checked overnight using a tool that asks devices to report their own status, it looked as if it didn't exist at all.
